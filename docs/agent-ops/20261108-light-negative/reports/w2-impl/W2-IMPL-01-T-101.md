## 3. Root cause
Missing subsystem, not a bug: no light palette block, no pre-paint init, no theme state/toggle. The fix builds the three mechanisms from the design (tokens + init + state).

## 4. Approach chosen and why
Mechanical build in design D5 order: (1) styles.css light block → (2) index.html head init → (3) components/theme.jsx + App state + both toggles + NewJob fix → (4) tests → (5) build+probe → (6) self/independent review. Alternatives B/C/D rejected per spec §6 (119+ `dark:` sites churn, no user control, asset-swap FOUC). DECISION: no `--warn-strong` (design D5 N — light `--warn` 165 73 10 is 5.64:1 on canvas / 5.39:1 on surface). INVARIANT: dark `:root` byte-identical (D1#1).

Implementation choices within the pinned surface:
- `applyTheme()` is the sole writer (attribute + meta + storage). `toggleTheme(current)` is pure so App's `useEffect([theme]) → applyTheme(theme)` stays the single apply site (StrictMode/HMR-safe, idempotent).
- App initial state reads `documentElement.dataset.theme` first (head init is source of truth on mount), falls back to `resolveTheme()`.
- `ThemeToggle` uses existing `.btn.btn-quiet` (token-only, 24px+ floor, `:focus-visible` accent outline ≥3:1 in both themes). No new CSS classes.
- `applyTheme()` creates the meta node if absent (jsdom), updates it if present — attribute/meta/storage always agree.

Explicitly NOT done (brief skip list): warn-strong token, tailwind darkMode, system listener, cross-tab storage listener, warn-chip (T-102), `wall_seconds`, palette tweaks.

## 9. Edge cases and abuse scenarios
Handled (and where):
- Storage read throws / `matchMedia` absent or throws → dark (`theme.jsx` + init guard chain); storage write throws → attribute+meta still flip (`applyTheme` try wraps only `setItem`).
- Hostile strings / case variants / empty → fall through (`resolveTheme` strict `===` checks).
- Sign-out must not clear preference: `logout` left untouched; test pins key survival.
- Smoke `getByRole('link', Runs/Models/…)` + `<nav>` queries: toggle kept outside `<nav>`; toggle label collides with no nav name (test asserts `nav.contains(toggle)===false`).
- Meta missing (jsdom) → `applyTheme` creates one node; production meta present → updated.
- Every stored value other than exactly `light`/`dark` is ignored (incl. `LIGHT`, whitespace).
Consciously not handled (by design): mid-session system switches + cross-tab sync (P-09 last-write-wins on reload); dev-mode unstyled flash (P-07 out of scope for the no-flash check; probe used production build).
Unknown: none for token-only scope. `ring-canvas` white gap around ResultLine dot in light is cosmetic/accepted per spec — recorded, not token-"fixed".
